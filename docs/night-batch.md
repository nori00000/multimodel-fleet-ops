# 야간 배치 — 자는 동안 일하는 함대

밤 사이 놀고 있는 저가 모델 쿼터에, 밤에도 급하지 않은 일(생성·조사·초안·변환)을 물린다.
아침에 일어나면 산출물이 준비돼 있고, 첫 판단은 그 검수부터 시작한다.

## 구조

```
~/night-batch/
  queue/     # 낮에 적재하는 지시서 (헤더: lane / timeout / fetch)
  running/   # 실행 중 (원자 mv = claim)
  work/      # 작업별 쓰기 루트 (유일한 쓰기 가능 경로)
  done/      # 완료 — 디렉토리 통째 원자 승격
  failed/    # 실패 + 크래시 복구분
```

러너([night-batch-runner.sh](../scripts/night-batch-runner.sh))는 launchd(23:30)로 발화해
큐를 순차 소화하고 05:30 이후 신규 작업을 멈춘다.

## 핵심 설계: 능력 경계 > 문서 규율

첫 설계는 "비가역 작업 금지, 산출물은 큐에만"이라는 **문서 규칙**에 의존했다.
교차 모델 크리틱(22건)의 판정: **BLOCK — "문서상 금지는 권한 경계가 아니다."**
무인 LLM은 사용자 계정 권한을 그대로 가지며, 조사 중 읽은 웹페이지의 간접 프롬프트 인젝션도 같은 권한을 얻는다.

수렴 결과, 규칙을 **능력 경계**로 교체했다:

1. **무도구 에이전트** — opencode 에이전트 정의([agent/night-batch.md](../agent/night-batch.md))로
   파일·셸·웹·스킬 도구를 전부 차단. 실증: 모델 자기보고 "available tools: none".
   도구가 없으면 인젝션은 나쁜 텍스트를 만들 뿐 행동이 되지 못한다 — 나쁜 텍스트는 아침 검수가 잡는다.
2. **웹접근은 러너가 대행** — 지시서의 `fetch:` URL을 러너가 결정론적으로(curl) 수집해 자료로 첨부.
   모델에게 웹 도구를 주지 않고도 조사 작업이 성립한다.
3. **경화 목록** (크리틱 수렴분): 프롬프트 argv 노출 제거(파일 첨부), 레인 정확 allowlist,
   타임아웃 정수 클램프 + 컷오프 인지(min(요청, 마감까지 잔여)), 프로세스 그룹 TERM→KILL,
   mkdir 원자 락 + PID 생존 확인, 크래시 복구(잔존물은 재실행 없이 아침 보고행),
   작업 디렉토리 통째 원자 승격(부분 상태 노출 없음).

## v2 백로그 (정직한 잔여)

전용 유저/OS 샌드박스, 비용·토큰 서킷브레이커, 기계적 아침 승격 게이트(quarantine 상태 머신),
작업 유형별 validator. 현재 버전의 안전선은 "무도구 + 대행 수집 + 아침 검수"다.
