# 라우팅 — 과제 유형 → 모델 레인

분업의 3목적: ① 고가치 모델 토큰 절약(오래 일하기) ② 단일 모델 편향·오류의 교차 탐지 ③ 병렬 시간 단축.
핵심 관찰: 멀티에이전트의 토큰 비용 경고(Anthropic 보고 기준 채팅 대비 ~15배)는 한 예산 안에서의 얘기다 —
구독이 여러 개면 **당면 제약이 총 토큰에서 판단 모델 쿼터 쪽으로 이동**하는 경향이 있다 (지연·검수 용량·통합 비용은 여전히 든다).

## 라우팅 표

| 과제 유형 | 패턴 | 목적 |
|---|---|---|
| 넓은 조사·스윕·수집 | 이기종 fan-out(여러 벤더 동시) → 결정론 게이트 → 판단 모델 종합 | ①②③ |
| 결합도 높은 구현 | 단일 실행 레인 + **비차단 교차 크리틱**(옆에서 병렬) + 합류점만 판단 | ①② |
| **작업물 크리틱 (코드·기획·추론)** | **교차 가족 필수**: Codex 산출→Claude 크리틱 / Claude 산출→Codex 크리틱. 동일 가족은 단독 승인 불가 | ② |
| 사실 검증 (원문·테스트 오라클 존재) | 가족 무관 저가 레인 OK ([실측 근거](fault-injection.md)) | ①② |
| 고부담 판정 | 이기종 소형 패널 다수결 — 단일 심판보다 덜 편향·저렴 (PoLL) | ② |
| 기계 작업 | 결정론 스크립트 우선(토큰 0) → 저가 모델 → 게이트 | ① |
| 대용량 읽기 | 대형 컨텍스트 모델 증류 → 판단 모델은 브리핑만 + 원문 스팟체크 | ① |

## 검증 2표면 — 이 구분이 핵심이다

1. **외부 오라클이 있는 사실 검증** (원문 대조·테스트·curl): 가족 무관, 저가 레인 충분.
   실측: 같은 가족(GPT) 모델이 GPT가 설계한 결함 5종을 전량 검출 — 오라클이 있으면 가족 편향이 recall을 훼손하지 않는다.
2. **오라클 없는 작업물 크리틱** (코드·기획·추론 리뷰): **교차 가족 필수.**
   근거: [Self-Preference Bias](https://arxiv.org/abs/2410.21819) (심판은 자기 출력을 체계적으로 선호),
   [LLMs Cannot Self-Correct](https://arxiv.org/abs/2310.01798) (외부 피드백 없는 자기교정은 실패·퇴행),
   그리고 반복된 실전 경험 — Codex의 오류는 Codex가 못 잡고 Claude가 잡으며, 그 역도 같다.

## 가드 3줄

- **fan-out은 breadth-first 전용** — 결합 작업의 병렬 분해는 비일관 산출을 낳는다 (Anthropic·Cognition·LangChain 합치).
  협업이 항상 이기지도 않는다: 단일 에이전트 베이스라인이 충분히 높으면 이득이 0~음수 ([capability saturation](https://www.nature.com/articles/s42256-026-01268-y)).
- **결정론 게이트는 날조 URL 전용** — 내용 오류 검출 0 실측. 비용 0이라 유지하되 단독 사용 금지, 모델 검증과 직렬.
- **지시서(SSOT) 품질이 최대 레버리지** — 멀티에이전트 실패의 41.8%가 사양/설계 결함 ([MAST](https://arxiv.org/abs/2503.13657)).
  "URL을 모르면 UNKNOWN이라 써라, 날조는 실패다" 한 줄이 출처 환각을 실측으로 거의 제거했다.
