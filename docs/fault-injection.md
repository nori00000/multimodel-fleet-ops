# Fault Injection — 검증 게이트를 실측하다

"검증 게이트가 있다"는 주장과 "검증 게이트가 잡는다"는 실측은 다르다.
가짜 결함을 심은 블라인드 코퍼스로 게이트 검출률을 직접 쟀다. 2라운드.

## 방법

- 실재 검증된 논문/블로그 출처 목록에 **의도적 결함**을 섞은 15항목 코퍼스를 만든다.
- 검증 레인들은 결함의 존재 여부·개수를 모른 채(블라인드) 전 항목을 원문 대조로 판정한다: VERIFIED / SUSPECT / REFUTED.
- 채점: 결함 검출률(recall), 클린 항목 오경보율, 결함 유형별 분해.

## 1라운드 — 설계자: Claude (결함 6종: 날조 URL·저자 오염·수치 변조·결론 반전·없는 주장·출처 바꿔치기)

| 검증 층위 | 검출 | 오경보 | 지연 |
|---|---|---|---|
| 결정론 (curl+제목 대조) | 1/6 | 0 | ~30s |
| Claude Sonnet + 웹 | **6/6** | 0 | 192s |
| Codex(GPT) + 웹 | **6/6** | 0.5 | **69s** |
| GLM + 웹 | **6/6** | 0 | 196s |
| 3레인 다수결 | **6/6** | **0** | — |

결정론 게이트는 예측대로 날조 URL만 잡았다(1/6) — "URL이 실재함 ≠ 주장을 지지함"의 수치 실증.

## 2라운드 — 설계자 교체: Codex(GPT)가 결함 설계 (본문 수준 스왑형 5종)

1라운드의 설계자 편향(같은 모델이 설계·채점)을 제거하고, 결함을 초록이 아닌 본문 수준으로 미묘화했다.
예: 논문 표의 두 벤치마크 점수를 맞바꾸기, "+80.8% / −70.0%"의 과제 귀속 반전.

| 검증 레인 | 검출 | 오경보 |
|---|---|---|
| Claude Sonnet | **5/5** | 0 |
| GPT Terra — **설계자와 같은 가족** | **5/5** | 0 |
| GLM | **5/5** | 0 |

15항목 전체에서 3레인 판정 만장일치.

## 발견

1. **게이트는 실측으로 성립** — 설계자를 바꾸고 결함을 미묘화해도 2라운드 연속 전량 검출·오경보 0.
2. **가족 상관은 오라클이 있으면 무해** — 같은 가족(GPT)이 GPT 설계 결함을 전량 검출.
   교차 가족이 꼭 필요한 곳은 사실 대조가 아니라 **오라클 없는 작업물 크리틱**이다 ([routing.md](routing.md) 검증 2표면).
3. **보너스 — 심지 않은 진짜 오류 발굴**: 검증 레인들이 코퍼스의 "클린" 항목에서 실제 전파 오류를 잡았다.
   여러 레인이 "180개 구성"이라 회상한 논문의 실제 초록은 **260개**였다 — 3개 레인이 같은 오류를 냈고
   종합 문서까지 전파됐던 것을 교차 검증이 발굴, 원문 grep으로 확정.
4. **한계 (정직하게)**: 결함이 원문 접근 가능한 수준이었고, 두 라운드 모두 "검증하라"는 지시가 있었다.
   실전의 위험은 검증 지시 자체가 없는 경로다 — 그래서 구조 규칙("조용한 소비처 앞 게이트 의무화")이 본질이다.
