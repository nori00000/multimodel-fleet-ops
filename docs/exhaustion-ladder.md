# 소진 사다리 (The Exhaustion Ladder)

토큰 소진을 **사고가 아니라 설계된 상태 전이**로 만드는 5단 사다리.
각 단은 "누가 판단하고, 누가 실행하고, 누가 검증하는가"를 재배정한다.

## 사다리

| 단계 | 트리거 | 판단 (Advisor) | 실행 | 검증/크리틱 |
|---|---|---|---|---|
| ① 정상 | — | 최상위 모델 (예: Claude Fable/Opus) | 중위 모델 에이전트 + Codex CLI | 교차 벤더 크리틱 (Codex) |
| ①.5 절약 모드 | 판단 모델 사용률 ≥75% | 최상위 모델 — **지휘 전용** (실행·대량 읽기 전부 외부화) | 외부 레인 | 동일 |
| ② 승계 | 최상위 모델 소진 | 차상위 모델 자동 승계 (실행 티어는 한 단계 하향해 승계 모델 쿼터를 판단에 보전) | 하위 모델 + Codex | 비가역·고영향 판정엔 교차 크리틱 **필수** |
| ③ 무판단 모드 | 주력 벤더 전체 소진 | 없음 — 판단 필요 작업은 큐 적립 | 이미 내려진 결정의 기계적 실행·결정론 검증만 | (적립) |
| ④ 예산 스택 자율 | 2차 벤더까지 소진 | 저가 스택 최상위 (예: DeepSeek V4 Pro) | 분해→탐색(Flash)→구현(GLM)→**독립 리뷰(MiMo)**→통합(Pro) | 스택 내 3가족 교차 유지 |

## 복귀 (failback) 규칙

1. 리필 감지 시 **한 단계씩** 상위 복귀 (건너뛰기 없음).
2. **복귀 첫 판단은 폴백 기간 산출물의 스팟체크** — 이를 위해 폴백 레인 산출물엔 생성 레인을 반드시 명시한다 (폴백을 숨기면 품질 회귀가 조용해진다).
3. 전환·복귀는 **새 작업부터 적용** — 진행 중 작업은 시작 시점 배정을 유지 (재배정 경합 방지).
4. 전면 정지 금지 — 단, 전 레인 불가·반복 장애 시엔 정지가 정답이다.

## 왜 이 모양인가

- **②에서 실행 티어를 하향하는 이유**: 승계한 모델의 쿼터를 판단에 보전. 판단이 가장 비싼 자원이다.
- **②에서 교차 크리틱을 "비가역·고영향 한정"으로 좁힌 이유**: 소진 국면에 필수 게이트를 늘리면 크리틱 풀이 먼저 마른다 — "소진-유발 복잡도 폭발"은 교차 모델 크리틱이 잡아준 우리 자신의 설계 결함이었다.
- **④에서도 리뷰를 다른 가족(MiMo)에 맡기는 이유**: 교차 가족 검증 원칙은 예산 스택에서도 유지된다. 같은 가족은 같은 맹점을 공유한다.

## 자동화 수준 (정직하게)

- 하강(①→②)은 대부분의 CLI가 자동 처리. 복귀는 **세션 경계에서 자동** (리필 후 새 세션이 기본 모델로 시작).
- 세션 시작 훅([quota-status.sh](../scripts/quota-status.sh))이 잔량과 권고 단계를 표시 — 반자동.
- 세션 중 자동 상향 전환은 구조적으로 어렵다 (판단 모델은 대화 컨텍스트 안에 산다).
